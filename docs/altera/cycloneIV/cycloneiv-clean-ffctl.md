# Cyclone IV GX FF controls, clock sources, carry-in (#165, 2026-10-30)

Code: `lifters/cycloneiv_clean/ffctl.py` (FfCtl), used by `emit.py` (`Builder._ff_controls`). Check: `scripts/cycloneiv_clean_ffctl_check.py`. Test: `tests/cycloneiv_clean/test_ffctl.py`.
Conditions: EP4CGX150, Quartus 25.1 asmdb, corpus `corpus/cycloneiv`, static analysis (libcomp_asm decompile via snapshot `ctl_decode`) + existing builds only (0 new builds).

## Value law
- `ASMDB_ARCH_GROUP_STD::select`: every bit of a mux entry is inverted when its `arch_value` is 0 (law from `docs/altera/cycloneIV/cycloneiv-clean-io.md`; `asmdb_select.std_select`).
- `arch_value` 0 groups of the LAB: `LE_CLOCK_SELECT`, `LE_CLEAR_SELECT`, `LE_USE_CARRY`, `LAB_ENABLE_CE` gi 0/1, `LAB_CLR_INVERT_PAIR`, `LAB_INVERT` gi 5. Vendor value = NOT bit.
- Explains three earlier empirical facts: LE_CLOCK_SELECT bit 1 = mux gi 0, LE_USE_CARRY bit clear = carry, ENABLE_CE bit 0 = enable used.

## LAB signals (vendor writers, libcomp_asm `process_end_of_phase`)
| Signal | Group | Inputs (input number i) | Used when |
|---|---|---|---|
| clock k=0,1 | `LAB_CLOCK_FAST_MUX` gi k (@0x15e138) | 0..3 = LAB_CONTROL_MUX i, 4..9 = BLK_CLK_BUF line i-4 (value = RE index + base) | always |
| aclr k | `LAB_CLEAR_FAST_MUX` gi k (@0x15deba) | 0..3 = LAB_CONTROL_MUX, 4..9 = BLK_CLK_BUF line (shared 6 second-level bits), 10 = none | decoded input != 10 |
| enable k | `LAB_CE_FAST_MUX` gi k (@0x15dd22) | i = LAB_CONTROL_MUX i | `LAB_ENABLE_CE` gi k value 1 (CE index == clock index, `process_atom`@0x15f628) |
| sclr | `LAB_SYNC_CLR_FAST_MUX` (@0x15eb62) | i = LAB_CONTROL_MUX i | `LAB_ENABLE_SYNC_SIGNALS` value 2, 3, 5 |
| sload | `LAB_SYNC_LOAD_FAST_MUX_MAG` (@0x15ec60) | i = LAB_CONTROL_MUX i | value 1, 3; value 4, 5 = sload tied high |
- `LAB_ENABLE_SYNC_SIGNALS` value (`process_atom`@0x15feb6): 1 sload only, 2 sclr only, 3 both, 4 sload = VCC, 5 sload = VCC + sclr; value -> bits through the mux map (3 bits).
- Select decode = inverse of the writer: pattern of `asmdb_select.select(first level, i)` + `(second level, nxt[i])`; most constrained matching input wins (FREE second level = unconstrained).
- RE-type constants in the writers (0x11c, 0xdc, 0xe1, 0x1b0, ...) are CDB_RE types, not `DEV_ELEMENT_ENUM` values (the sclr / sload writers accept only 0x11c as source and GT shows LAB_CONTROL_MUX sources, so 0x11c = LAB_CONTROL_MUX is inferred; the enum has MEDIUM_EAB_BUFFER at 284).
- Shared bits (vendor-declared): `LAB_CLOCK_FAST_MUX` gi 0 second-level bit = `LAB_SYNC_LOAD_FAST_MUX_MAG` bit (LAB_CONTROL_MUX 0/1 pair shared by clock 0, aclr 0, enable 1, sload); gi 1 second-level = pair 2/3 (clock 1, aclr 1, enable 0, sclr).
- Unused `LAB_CLEAR_FAST_MUX` gi reads first-level 00 = "line" when the other gi selects a line (second-level bits shared). `ASM_LE_CLEAR_SELECT::process_atom`@0x16baea gives an idle LE the signal whose real source is NULL: equal line selections of gi 0 and gi 1 = signal 1 unused (`aclr_shared_line`, counted).

## Per LE
- clock / enable group g = value of `LE_CLOCK_SELECT` (= mux gi); aclr group = value of `LE_CLEAR_SELECT`.
- `LE_USE_SYNC_CLEAR` and `LE_USE_SYNC_LOAD` (DECISION mux, value 1 writes the one real bit; both groups write the same bit): bit = sclr term connected OR sload term connected, so a set bit also proves a register exists. LAB state 4 / 5 + bit: sload tied high, D = ASDATA (DATAC input), also when the LE has a LUT.
- `LE_USE_REGISTER_FEEDBACK` (@0x16c294) = 1: the LE's comb LUT's own DATAC input is its own register (F-010, validated). Does NOT mean the LE's independent sload/ASDATA mechanism also sources from its own register -- the comb function and the sload path are separate logical consumers of the same physical gi-2 mux, and an LE can read its own register in the comb function while sync-loading from a different signal (#183, F-020 pt2 below). `emit.py._asdata_source` runs the plain LE_LUT_INPUT/LI-LL lookup first and falls back to `LE_USE_REGISTER_FEEDBACK` only when that lookup is itself undecoded.
- `LE_USE_CARRY` value 1 (bit clear) = carry-in connected. No chain use: carry-in term unconnected, cin = gnd; `cout = lut4(mask, dataa, datab, cin, 0)` in every mode (`cycloneiv_atoms.v`).

## Polarity (read off specimens; the vendor signal-id table, ASM_SINGLE_LAB_MODEL_BASE ctor jump table, is not read)
- `LAB_INVERT` gi k = line k of the vendor `VIRTUAL_LAB_LINE` table (`ASM_LAB_MODEL_TITAN` ctor@0x166e26, 11 lines of 20 bytes at 0x3cda00; field 1 = signal mask 4 clock, 2 enable, 0x40 sload, 8 aclr, 0x20 sclr): 0 clk0, 1 ce0, 2 clk1, 3 ce1, 4 sload, 5 sclr; table lines 5..8 (third clock pair, the two aclr lines) are not LAB_INVERT lines for this die (aclr polarity = LAB_CLR_INVERT_PAIR). Order of lines 0..4 is the table order; gi 5 = sclr (table line 9) is the corpus reading (an inverted-sclr build exists), the builder that drops lines 5..8 (`ASM_SINGLE_LAB_MODEL_BASE` ctor) is not decoded.
- Value 1 = inverted for clocks from a BLK_CLK_BUF line; sources from LAB_CONTROL_MUX flip it (`look_up_signal_polarity`@0x1563ae: xor for source classes in mask 0x1f80). Net result in the netlist sense: clock inverted = value ^ (source is LCM); enable / sload / sclr inverted = NOT value (always LCM sources).
- aclr: `LAB_CLR_INVERT_PAIR` value bit k = polarity of aclr k (`process_end_of_phase`@0x15ee88), inverted = value bit ^ (source is LCM).
- Power-up level: no asmdb group, `ASM_REG_POWER_UP_MONITOR` writes no bits; every corpus dffeas is `power_up = "low"`. Modelled as power-up 0.

## Carry-in source
- `ASM_CARRY_CHAIN_MONITOR_BASIC::validate_chain_le_locations`@0xfb2b6: LE n > 0 <- LE n-1 of the same LAB; LE 0 <- LE 15 of the LAB at Y+1 (same X).
- Family flag `m_chain_skip_half_labs` (LE 8 may chain from LE 15 above): set per `base_family` (6 -> 1, 0xe / 0x10 -> 0, 0x38 -> 1); the family value of Cyclone IV GX is not read. Not modelled: LE 8 <- LE 7.
- No cross-LAB carry link exists in the 16,297 corpus builds (every carry-mode LE has its source in the same LAB, LE n-1; no LE 0 in carry mode): cross-LAB rule is vendor-code only.

## ASDATA gap resolved (2026-10-31, F-020, #182)
- Gap: `tmp/dji_microcode/build/build.json`'s image-specific undecoded count ("FF sync load: ASDATA (DATAC) source") was 131 of 35,873 FFs; the corpus check's own ASDATA samples above never hit it because the local corpus has no case where either sub-cause below fires on an ASDATA-carrying LE.
- Two sub-causes, both in `emit.py._asdata_source` (shared by the sload-tied-high D path and the normal-sload ASDATA field), both mirroring a convention the LUT's own DATAC-pin decode in `_logic` already used but ASDATA's decode had not adopted:
  1. **Register feedback** (9 of 131 image instances): `LE_USE_REGISTER_FEEDBACK` (F-010) set <-> the LE's DATAC input is its own register, same as `lut_datac_register_feedback`. Checked first, before the LE_LUT_INPUT mux fallback.
  2. **Genuinely unselected mux = tie to `1'b1`** (122 of 131): `self.sel[lab, le, 2] == -1` (no first-level LE_LUT_INPUT hot bit) is the exact condition the LUT-pin path already treats as `UNCONNECTED` (`lut_pin_unconnected`, the sourced "every unconnected LUT input... is VCC" convention) rather than undecoded; ASDATA's decode was flagging it undecoded instead of applying the same tie. Carry-mode LEs are NOT excluded from this path: the image has sload FFs whose LE is simultaneously carry mode (gi 2 = cin for the comb function) with a resolvable, non-carry ASDATA value on the same mux bits (register-mode reads CDB_ATOM iterm 0x20, comb reads iterm 0xe -- two logical uses of one physical mux, confirmed by `ASM_LE_LUT_INPUT::process_atom`@0x16c464's own branch). An ambiguous table entry (`-2`) or a selection resolving to a record absent from the graph still counts as undecoded, matching the LUT pin exactly.
- Image result (re-decoded from the same bitstream, `scripts/cycloneiv_clean_image_build.py`): undecoded ASDATA 131 -> **0**; LUT/FF/IO/PLL/M9K/MAC counts and package (F672) unchanged, confirming the same image. Breakdown of the 12,288 FFs with a real (non-tied-high) sload: `ff_d_from_asdata` 9,274 (sload-tied-high D path) + `ff_asdata_used` 3,014 (normal sload path, resolved) + `ff_asdata_unconnected` 122 (tied `1'b1`).
- Local 485-design corpus: `ff_asdata` 1,631 / 0 / 0 / 0 before and after both fixes (no local design exercises either gap; not a fitted-to-zero result -- the corpus genuinely has neither trigger condition). Fast tier (134 designs) and full tier (532 designs, `corpus_keep.tsv`) gates: 0 change in any column across both fixes (full tier's pre-existing 193 missing pips / 51 missing nets, #177, unrelated to ASDATA).
- Found and fixed alongside: `scripts/cycloneiv_clean_emit_check.py`'s `gt_producer` only special-cased an `LE_BUFFER` root to resolve a GT net to its real `("LC"|"FF", x, y, le)` producer; a net whose first RCF root is `LOCAL_LINE` (same LE output, LAB-internal copy) fell through to a bare `SRC` tuple, which showed as 2 `ff_asdata` "wrong:root" faults on `gxct_d_sload_one` when the ASDATA scorer was switched from a routing-record comparison to a producer-tuple comparison (needed because register-feedback ASDATA, like register-feedback DATAC, has no routing record at all). `gt_producer` now tries every root of the net for an `LE_BUFFER`/`LOCAL_LINE` match before falling back; confirmed no change to any other design's score.

## ASDATA register-feedback regression fixed (2026-10-31, #183, F-020 pt2)
- F-020 (above) checked `LE_USE_REGISTER_FEEDBACK` BEFORE the plain LE_LUT_INPUT mux lookup in `_asdata_source`, reasoning the bit means the same thing for ASDATA as for the LUT's own comb DATAC pin (F-010). Wrong for the ASDATA/sload use: of 5,237 image LEs on the ASDATA call path (forced sload-tied-high, `sync_state` 4/5, or explicit sload mux, `sync_state` 1/3) with the bit also set, **5,228 have a plain-lookup target that is a real, different signal** (a different LE's output, an M9K read, etc.) that register-feedback-first silently discarded as a self-loop (own D = own Q forever, impossible to ever change from reset). Only 9 of 5,237 have no other resolution (the F-020 pt1 target case).
- Root cause: `LE_USE_REGISTER_FEEDBACK` (`ASM_LE_USE_REGISTER_FEEDBACK::process_atom`@0x16c294) is a fact about the LE's comb LUT's own DATAC pin (validated, F-010). The LUT's comb function and the register's independent sload/ASDATA mechanism are two separate logical consumers of the same physical gi-2 mux wiring; an LE can legitimately have its comb function read its own register (one of up to 4 LUT inputs, used for e.g. `next = f(state, ...)`) while its sload path, separately, loads from a different, unrelated signal. Confirmed directly: for every one of the 5,228 LEs above, the comb LUT's own pin[2] genuinely does equal the LE's own FF output (matching F-010 exactly) AND the plain LE_LUT_INPUT lookup for the SAME gi-2 mux slot resolves to a different, real record -- the two uses disagree, and only the plain lookup is correct for ASDATA.
- Found via the DJI AF3 SHA-1 engine (`docs/altera/cycloneIV/cycloneiv-clean-af3-engine.md`): its a/b/c/d/e round registers' LUTs read their own register (comb round function) while separately sync-loading from the W-schedule M9K RAM each cycle -- exactly the untested combination. 15 of the engine's 218 FFs hit it; `d <= d` (self-loop) made the whole downstream datapath compute zero, including the SHA-1 message words W0/W12 (`lightbridge-fpga.md` section 8, awtoau/pluribus#183).
- Fix: `_asdata_source` now runs the plain LE_LUT_INPUT/LI-LL lookup FIRST; `LE_USE_REGISTER_FEEDBACK` is consulted only as a fallback when the plain lookup is itself undecoded (`s == -1`, `sel_only`, `s < 0`, or an absent record) -- the same precedence the comb-pin's own decode in `_logic` keeps unchanged (carry mode first, register feedback only for a real register, `self.ffp[lab, le]`).
- Verified: AF3 engine's fresh-rebuild test (`tests/cycloneiv_clean/test_af3_engine.py`) passes again, unmodified W0/W12 = `01118789`/`79465213` matching the documented key. Image ASDATA undecoded count stays 131 -> 0 (F-020 pt1's fix not regressed). Local 485-design corpus `ff_asdata`, fast tier (134 designs) and full tier (533 designs) gates: 0 change in any missing/extra/wrong column.
- New targeted specimen closing the coverage gap `scripts/cycloneiv_clean_regfb_sload_specimen.py` -> `corpus/cycloneiv/gxct_e_regfb_sload` (registered in `reference/corpus_keep.tsv` and `reference/gate_fast.tsv`): one LE whose comb LUT's DATAC pin is wired to its own register (forces `LE_USE_REGISTER_FEEDBACK`) while its independent sload/ASDATA is wired to a different signal; fails `ff_asdata` (`wrong:root`) on the buggy code, passes on the fix -- the 485-design corpus and the pre-#183 `gxct_*` family never exercised this combination.
